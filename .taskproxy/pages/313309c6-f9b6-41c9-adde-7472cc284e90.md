### Setup

<webui-page-segment>

Plugins build for WebAssembly, so add that target once.

```pwsh
rustup target add wasm32-unknown-unknown
```

</webui-page-segment>

### Testing

<webui-page-segment>

Every test runs natively, with a fake Task Proxy (`testing::FakeHost` in the Jira plugin), so no WebAssembly runtime is needed.

Run all tests

```pwsh
cargo test --workspace
```

Run the Jira plugin's tests

```pwsh
cargo test -p taskproxy-jira
```

Run the SDK's tests

```pwsh
cargo test -p taskproxy-plugin-sdk
```

Run tests by name, such as every View test

```pwsh
cargo test -p taskproxy-jira views
```

Lint, failing on any warning, as CI does

```pwsh
cargo clippy --workspace --all-targets -- -D warnings
```

Format the code

```pwsh
cargo fmt --all
```

</webui-page-segment>

### Build and try a plugin in Task Proxy

<webui-page-segment>

Build every plugin into `dist/<id>`, with its `plugin.json` and `plugin.wasm`.

```pwsh
./scripts/build.ps1
```

Then in Task Proxy, click the puzzle piece button beside Icons & Emojis, click **Install from folder**, and choose `dist/jira`. Install again after each build to try the change; your settings and saved data are kept.

</webui-page-segment>

### Jira screens for the website

<webui-page-segment>

The TaskProxy.com screenshots draw the Jira plugin's own pages for a made-up project, from `src/demo.rs`. Write them into TaskProxyApp, which `publish.ps1` also does.

```pwsh
cargo run -p taskproxy-jira --example demo -- ../TaskProxyApp/tools/capture/fixtures/jira
```

Then capture the screenshots in TaskProxyApp, into the website checkout.

```pwsh
Push-Location ../TaskProxyApp
npm run capture -- plugin-screenshots
Pop-Location
```

</webui-page-segment>
