### Before every commit

<webui-page-segment>

Run this before each commit, or choose it as the Git Controller's **Run Before Commit** script. It:

1. formats the code
2. gives each plugin that changed since the last commit a new patch version, in its `Cargo.toml` and `plugin.json` (a change to the SDK changes every plugin)
3. lints and runs every test
4. builds every plugin
5. updates TaskProxyApp's test plugin, when it changed, and its Jira screens

If anything fails, it stops, and the commit should wait.

```pwsh
./scripts/publish.ps1
```

A minor version for the changed plugins

```pwsh
./scripts/publish.ps1 -Version minor
```

A major version for the changed plugins

```pwsh
./scripts/publish.ps1 -Version major
```

Leave the versions as they are

```pwsh
./scripts/publish.ps1 -SkipVersionBump
```

Leave TaskProxyApp alone

```pwsh
./scripts/publish.ps1 -SkipApp
```

When TaskProxyApp files change, commit them in TaskProxyApp too.

</webui-page-segment>

### Releasing

<webui-page-segment>

<webui-quote theme="warning">

Every push to `main` publishes every plugin to the catalog at `https://cdn.myfi.ws/apps/task-proxy/plugins/catalog.json`, where installed copies of Task Proxy find it.

</webui-quote>

The deploy workflow tests, builds, signs each plugin's `plugin.json` and `plugin.wasm` with the Task Proxy update key, and uploads them by version with `catalog.json`. It uses the same GitHub secrets as TaskProxyApp: `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, and the `CDN_*` SFTP settings.

Build, sign, and write the catalog locally, as CI does. This needs the signing key in `TAURI_SIGNING_PRIVATE_KEY`, as its contents rather than a path.

```pwsh
./scripts/build.ps1 -Sign -Catalog
```

</webui-page-segment>
