# Plugin spec 0.1

This is spec line 0.1, currently at **0.1.3**. Anything added after 0.1.0 is marked with the patch that added it. Versioning and compatibility are in the [spec README](README.md), and advice beyond the rules is in the [guidelines](guidelines.md).

**MUST** and **MUST NOT** are rules: Task Proxy refuses a plugin that breaks one, or the plugin misbehaves. **SHOULD** is strong advice.

All JSON names are camelCase. Hosts and plugins **MUST** ignore fields they don't know, which is what lets a patch add them.

## 1. Package

A plugin is two files:

- **`plugin.json`:** its manifest. See section 2.
- **`plugin.wasm`:** a WebAssembly module for `wasm32-unknown-unknown`, at most 20 MB.

**How it runs:**

- **Runtime:** [Extism](https://extism.org), so a plugin can be written in any language with an Extism PDK. The Rust SDK in this repo is the reference.
- **No WASI, and no Extism HTTP or file access.** The plugin's only import is `taskproxy_host` in the `extism:host/user` module (section 5).
- **Installing:** from the signed catalog (section 9) or, for development, from a folder holding both files, which Task Proxy marks as unsigned.

## 2. Manifest

| Field | Type | Required | Rules |
|---|---|---|---|
| `id` | string | yes | A slug: lowercase letters, digits, and dashes, starting with a letter, at most 64 characters. It is the plugin's folder, route, and storage name, so it never changes. |
| `name` | string | yes | Shown to the user. Not blank. |
| `version` | string | yes | The plugin's own version, `major.minor.patch` numbers. Every release raises it. |
| `spec` | string[] | yes (0.1.1) | The spec versions the plugin supports, one for each line, each the lowest patch it needs, such as `["0.1.0"]`. |
| `apiVersion` | number | while on line 0.1 | `1`, for Task Proxy 0.1.121 and earlier (README, "Before spec versions"). Without `spec`, it is read as spec 0.1.0. |
| `description` | string | no | A sentence or two, shown in the catalog and before installing. |
| `category` | string | no | A slug, such as `issue-tracking`. The website groups plugins by it. |
| `icon` | string | no | An icon name (section 8.6). |
| `permissions` | object | no | Everything the plugin may reach (section 3). Leaving it out asks for nothing. |
| `pages` | object[] | no | The plugin's pages (section 4.1). |
| `contributes` | string[] | no | Other places it shows up (section 4). |

`spec` is required by these rules and by the publish build. Task Proxy accepts a manifest without it only as `apiVersion: 1`, which is spec 0.1.0.

Task Proxy refuses a manifest that:

- has an id, category, or page id that is not a slug
- has a blank name
- has a version that is not three numbers
- names no spec version Task Proxy supports
- breaks a rule in section 3

## 3. Permissions

`permissions` lists everything a plugin may reach. Task Proxy shows the list before installing, and refuses any host call or host action it does not allow. The catalog shows the same permissions, and an install whose signed manifest asks for any others is refused.

### 3.1 `hosts`

The domains the plugin may send HTTPS requests to.

- **Exact host:** `api.example.com` matches only that host.
- **Subdomains:** `*.example.com` matches any subdomain, such as `team.example.com` or `a.b.example.com`, but not `example.com` itself.
- **Refused:** a pattern without at least two labels, such as `*` or `*.com`; a URL, port, or path; and a label that is not letters, digits, and inner dashes.

### 3.2 `variables`

The settings a plugin reads with the `var` host call. Each one is an object:

| Field | Type | Rules |
|---|---|---|
| `key` | string | Letters, digits, `_`, and `-`. **MUST NOT** start with `app-` or `session-`, which are Task Proxy's own state. |
| `label` | string | Shown beside the input. |
| `secret` | boolean | Masked when entered, saved encrypted, never shown again, and only sent to this plugin. |
| `help` | string | One line under the input, such as where to create a token. |

The user enters these in the Plugins drawer, as settings for the open project. Section 6.2 covers how they are looked up.

### 3.3 `git`

| Value | Allows |
|---|---|
| `currentBranch` | The `currentBranch` host call. |
| `createBranch` | The `git.createBranch` host action. |

Any other value is refused.

### 3.4 `processes` (Draft 0.1.4)

Section 10 describes this permission.

## 4. Contribution points

### 4.1 `pages`

Each page becomes a nav entry under the plugin's name, at `/plugin/<id>/<page>`.

| Field | Type | Rules |
|---|---|---|
| `id` | string | A slug, unique in the plugin. |
| `name` | string | The nav entry's text and the page's title. |
| `icon` | string | An icon name (section 8.6). |
| `hidden` | boolean | Kept out of the nav, for pages only opened from another page, such as one issue. |

The address's query becomes the render request's `params`: `/plugin/jira/issue?key=PROJ-1` sends `{"key": "PROJ-1"}`. A query value that is JSON text is sent as text, so the plugin parses it.

### 4.2 `gitBranchInfo`

The plugin's `branch_info` export draws a small card under the Git Controller's branch picker, about the branch checked out in the open project's selected repo.

### 4.3 `notifications`

The plugin's notifications show in Task Proxy's Alerts panel:

- **Polling:** Task Proxy calls `notifications` every two minutes, and again when the project or a plugin changes.
- **New ones** pop up. Those found when Task Proxy starts only join the list.
- **One the plugin stops listing** is removed.
- **Closing one** calls `notification_read` with its id.

Any other value in `contributes` is ignored, so a plugin can name a point added in a later patch.

## 5. Calls between Task Proxy and a plugin

### 5.1 Envelopes and limits

Every export takes one JSON value as input and returns `{"ok": <result>}` or `{"error": "<message>"}`. Task Proxy shows the message to the user, so it **SHOULD** be a sentence they can act on.

- **Fresh instance:** each call runs in a new instance of the compiled module, so a plugin keeps nothing in memory between calls. Anything it keeps goes in storage (`storeSet`).
- **Time:** a call gets 30 seconds of WebAssembly time. Time waiting on HTTP does not count.
- **Memory:** a call gets 64 MB.
- **Failures:** a trap, timeout, or invalid output is reported as an error, and the next call starts clean.

### 5.2 Exports

| Export | Required | Input | Result |
|---|---|---|---|
| `render` | yes | `{"page": string, "params": object}` | A UI node (section 8): the page's content. |
| `action` | yes | `{"page", "pageParams", "action", "params", "form"}` (below) | An action result (section 7). |
| `branch_info` | with `gitBranchInfo` | `{"branch": string}` | A UI node, or `null` for nothing to say about it. |
| `notifications` | with `notifications` | `{}` | A list of notifications (below). |
| `notification_read` | with `notifications` | `{"id": string}` | Anything. It is ignored. |

**An action's input:**

- `page` and `pageParams`: the page the action came from, and that page's params.
- `action`: the id of the action that was clicked (section 8.3).
- `params`: that action's own params.
- `form`: the values of the form it submitted, or `{}`. Field values are covered in section 8.4.

Task Proxy also calls `action` without a click, to ask for choices: a `select` node's `options` action, and a field's `suggest` action. Those return `options` (section 7) and **MUST NOT** change anything.

**A notification:**

| Field | Type | Rules |
|---|---|---|
| `id` | string | Unique among the plugin's notifications, and the same each time it is listed. |
| `title` | string | Required. |
| `text` | string | Optional. |
| `theme` | string | `info`, `success`, `warning`, or `danger`. |
| `time` | string | When it happened, shown as written. |
| `links` | object[] | Each is `{"text", "page", "params"}`. Wherever `text` appears in the title or text, it links to that page of the plugin. |

### 5.3 Host calls

A plugin calls `taskproxy_host` with one JSON request, whose `op` names the call. The answer is `{"ok": <value>}` or `{"error": "<message>"}`, and Task Proxy answers a request it does not understand with an error. New calls are new `op` values, never new imports.

| `op` | Request | Answer | Needs |
|---|---|---|---|
| `var` | `{"key"}` | string, or `null` when not set | the key in `permissions.variables` |
| `storeGet` | `{"key"}` | the saved JSON value, or `null` | nothing |
| `storeSet` | `{"key", "value"}` | `null`. A `null` value removes the key. | nothing |
| `projectFileRead` | `{"path"}` | the file's text, or `null` when there is none | an open project |
| `projectFileWrite` | `{"path", "text"}` | `null` | an open project |
| `currentBranch` | `{}` | the checked-out branch's name, or `null` | `git: currentBranch` |
| `now` | `{}` | milliseconds since the Unix epoch | nothing |
| `http` | `{"request": {"method", "url", "headers", "body", "encoding"}}` | `{"status", "body"}` | the URL's host in `permissions.hosts` |
| `hostInfo` (0.1.1) | `{}` | `{"app", "spec", "platform"}` | nothing |

**Storage:**

- Each plugin has its own storage, kept encrypted with Task Proxy's data and shared by every project.
- It is saved after any call that changes it.
- Removing the plugin deletes it.

**Project files:**

- `path` is relative to `.taskproxy/plugins/<id>/` in the open project, which is shared with the team through git.
- A path that is absolute, uses `..`, or leaves that folder through a link is refused.
- Files are text, at most 1 MB to write.

**HTTP:**

- HTTPS only, with no redirects. A plugin that wants to follow one makes the next request itself.
- At most 10 MB of response body.
- Credentials go in headers, never in the URL: a URL with a user name or password is refused.
- `body` is text, usually JSON.
- `encoding: "base64"` (0.1.3) answers with the body's bytes as base64, for images and other files that are not text. Older hosts answer with text, which corrupts such files, so check `hostInfo` first.
- A response with any status is answered with `ok`. Only a refused or failed request is an error.

**`hostInfo`:**

- `app` is Task Proxy's version.
- `spec` is the spec version Task Proxy runs this plugin with.
- `platform` is `linux`, `macos`, or `windows`.

## 6. Where a plugin shows up

### 6.1 Turned on, and set up per project

- **Turned on or off:** each installed plugin is turned on or off for the user. A plugin that is off is never called.
- **Set up per project:** a plugin shows in a project only when that project is set up for it.
  - A plugin that declares variables is set up when the project has a value for every one of them. The value comes from the project's settings for the plugin or from the project's own variables.
  - A plugin that declares none is set up when the user turned it on for that project.
- **A project that is not set up:**
  - shows no nav entry for the plugin
  - gets no branch cards or notifications from it
  - refuses `render` and `action`
  - shows the plugin's pages, if opened by address, as its setup
- **Global variables never set a plugin up,** since they would reach every project.

### 6.2 Settings

- **Kept per project.** The values the user enters are a sign-in, and a project uses one sign-in or none. Projects can share a sign-in.
- **Kept apart:** they are saved encrypted, apart from Task Proxy's variables, so project pages and scripts cannot read them.
- **Lookup order for `var`:** the open project's own variable of that name, then the project's sign-in.

### 6.3 Routes

- **A plugin's pages** are at `/plugin/<id>/<page>?<params>`.
- **Navigating:** a plugin moves between its own pages with `navigate` (section 7). It cannot open other Task Proxy pages or reach another plugin.

## 7. Action results

Every field is optional. An empty result `{}` changes nothing. Fields are applied in this order:

| Field | Type | Effect |
|---|---|---|
| `message` | `{"text", "theme"}` | Shows a short alert. `theme` is `info`, `success`, `warning`, or `danger`. |
| `closeDialog` | boolean | Closes the dialog the action came from. |
| `navigate` | `{"page", "params", "side?", "cover?"}` | Opens a page of the plugin, or the same page with other params, which draws it again. It also closes any dialog. With `side` (0.1.4), the page opens beside the current one instead (below). |
| `dialog` | `{"title", "ui"}` | Opens a dialog showing that UI. |
| `ui` | node | Replaces the page's content, or the dialog's when the action came from a dialog. |
| `refresh` | boolean | Draws the page again. From a dialog, this redraws the page behind it. |
| `options` | `{"value", "label"}[]` | The choices, answering a `select` node's `options` action or a field's `suggest`. |
| `cover` (0.1.4) | boolean | Changes whether the page shown beside this one covers it, as `navigate`'s `cover` does, keeping the page that shows there (below). |

**`side` (0.1.4):** the page opens beside the one the action came from, in a split the user resizes, and the page it came from stays as it was, such as a list beside the issue picked from it. Where the window is too narrow for both, the side page covers the other, with a button to switch between them. A page shown beside another has no address of its own: what it navigates to opens in its place, except the page beside it, which opens there. A `refresh` from it draws both again. The host remembers the side page per project, so going back to the page later opens it beside it again, until the user closes it or opens it as its own page. Older hosts open the page in place of the current one, so it is safe to send to any host.

**`cover` (0.1.4):** with `side`, the side page covers the page it came from at any width, as it does in a narrow window, with a button on each to switch between them. Use it when the user would rather see one page at a time. The host remembers it with the side page. A result's own `cover` changes it for the page already beside this one, such as when the user turns a split view off or on, and does nothing when there is none. Hosts that support `side` but not `cover` show the pages side by side, so send `cover` only to hosts that support 0.1.4.

## 8. Screens

Plugins describe their screens as JSON nodes, and Task Proxy draws them with its own components. A plugin never sends HTML, CSS, or script.

### 8.1 How nodes are drawn

- **Text** is set as text.
- **`markdown`** is the only rich text, and Task Proxy sanitizes it.
- **An unknown `type`** is drawn as a placeholder. A plugin **SHOULD NOT** rely on that: when it needs a node from a later patch, it lists that patch in `spec`.
- **Themes:** `primary`, `secondary`, `tertiary`, `info`, `success`, `warning`, and `danger`. An unknown theme is drawn without one.

### 8.2 Nodes

Every node has a `type`. Fields marked `?` are optional.

| `type` | Fields | Draws |
|---|---|---|
| `stack` | `children` | Children one above another. |
| `row` | `children` | Children side by side, wrapping. |
| `toolbar` | `children` | Buttons and links in a bar. |
| `heading` | `text`, `level?` (1–4, default 2) | A heading. Pages start at 2, below the page's title. |
| `text` | `text`, `muted?`, `strong?` | A paragraph. |
| `markdown` | `text`, `images?` (0.1.3), `toggle?` (0.1.3) | Sanitized markdown (below). |
| `badge` | `text`, `theme?` | A small label. |
| `link` | `text`, `action` | Text that runs the action. |
| `button` | `action`, `theme?`, `on?` (0.1.4) | A button labeled with the action's `label` and `icon`, or a switch with `on` (below). |
| `properties` | `items: [{"label", "value": node, "edit?": node}]` | Labels and values, as for an issue's fields (below). |
| `table` | `columns`, `rows` | A table (below). |
| `select` | `text`, `theme?`, `options: action`, `action` | A value changed in place (below). |
| `clip` | `text`, `max?` (30), `tip?` (100), `action?`, `always?`, `muted?`, `theme?` (0.1.4) | Text cut to `max` characters (below). |
| `section` | `key`, `title`, `subtitle?`, `open?`, `children` | A collapsible section. |
| `panel` | `key`, `open?`, `children` | A part with no title, shown and hidden by the `toggle` host action. |
| `form` | `fields`, `submit: action`, `cancel?: action`, `buttons?`, `children?`, `inline?` (0.1.2), `changed?: action` (0.1.4) | A form (section 8.4). |
| `inputs` | `fields` | More of a form's fields, placed among its `children`. |
| `notice` | `text`, `theme` | A message in a colored box. |
| `empty` | `text` | What a list shows when it has nothing in it. |
| `reorder` (0.1.2) | `items: [{"id", "children"}]`, `action` | Items the user puts in order (below). |

**Remembered state:** whether each `section` or `panel` is open is remembered per plugin by its `key`, so a key **SHOULD** stay the same each time the page is drawn. `open` is only how it starts before the user opens or closes it.

**Tables:**

- **Columns** are titles, or `{"label", "action?", "sort?"}`. Clicking the title runs `action`, as to sort by that column. `sort` is `asc` or `desc`, and marks the column the table is sorted by.
- **Rows** are `{"cells": [node], "action?", "theme?"}` (`theme` since 0.1.4). Clicking a row runs its action.
- **Every other row is shaded,** so a wide table is easy to follow across.
- **A row's `theme` (0.1.4)** tints its background with that theme, blended with the row's own shade, as for a bug. Older hosts draw the row without it, so it is safe to send to any host.

**`button`:** **`on` (0.1.4)** makes the button a switch between two states, such as a view that is on or off. `true` draws it on and `false` off, and clicking it runs `action`, which **SHOULD** switch the state and draw the page again. A host that draws the switch colors it by its state and ignores `theme`. Older hosts draw a plain button with `theme`, so a plugin **SHOULD** give it a `theme` that shows the state, such as `primary` when on and `secondary` when off, and a `label` that names what it switches without the state, such as "Split view".

**`clip`:** **`theme` (0.1.4)** colors its text, as for an issue's type. Older hosts draw it without one.

**`select`:**

- Shows `text` as a button.
- When clicked, Task Proxy runs `options` and shows the choices it returns, so a long table doesn't load the choices for every row.
- Picking one runs `action` with `form` set to `{"value": "<choice>"}`.

**`markdown`:**

- Only markdown is rich text, and Task Proxy sanitizes it.
- **`images` (0.1.3)** names the images the markdown shows, by the name its `![alt](name)` uses, each a `data:image/...;base64,` URI of a PNG, JPEG, GIF, WebP, BMP, or AVIF. Task Proxy removes every other image, so a plugin can never load anything from the web, such as a tracking pixel. Older hosts show no images, so a plugin **SHOULD** send image references only to hosts that support 0.1.3.
- **`toggle` (0.1.3)** adds a switch between the rendered markdown and the text as written. It starts rendered.

**`properties`:** an item with **`edit` (0.1.3)** switches between its `value` and `edit` when its label is clicked, as to change a field with a form. Older hosts show only the value. To change a value picked from a list, use a `select` node as the value instead, which changes when it is clicked.

**`reorder` (0.1.2):**

- Each item shows a drag handle and its `children`. Item ids **MUST** be unique in the list.
- The user drags an item to a new place, or moves it with Alt+Up and Alt+Down.
- When the order changes, Task Proxy runs `action` with `form` set to `{"order": [<ids in their new order>]}`. Quick moves in a row are sent once.
- Hosts before 0.1.2 draw it as a placeholder. A plugin that also supports older hosts **SHOULD** check `hostInfo` and draw something else there, such as arrow links, as Jira's column editor does.

**`clip`:**

- Text longer than `max` characters is cut, with an ellipsis.
- Cut text shows its first `tip` characters as a tooltip, and runs `action` when clicked, such as to show all of it.
- With `always`, `action` runs even when nothing was cut.

### 8.3 Actions

Anything the user can click is an action:

| Field | Type | Rules |
|---|---|---|
| `id` | string | Sent to the `action` export. |
| `label` | string | The button's text, or the link's tooltip. |
| `params` | object | Sent with it. |
| `confirm` | string | A question asked first. The action runs only if the user agrees. |
| `icon` | string | An icon name (section 8.6). |
| `host` | object | A host action (section 8.5), run by Task Proxy instead of the plugin. |

### 8.4 Forms

Each field is an object:

| Field | Type | Rules |
|---|---|---|
| `name` | string | The key in `form`. |
| `label` | string | Shown with the input. |
| `kind` | string | `text`, `password`, `textarea`, `number`, `select`, `multiselect`, `checkbox`, or `hidden`. |
| `value` | any | The starting value: a string or number, `true`/`false` for a checkbox, or a list of strings for a multiselect. |
| `options` | `{"value", "label"}[]` | The choices for `select` and `multiselect`. |
| `required` | boolean | Must be filled in before the form is sent. |
| `placeholder` | string | |
| `help` | string | Shown with the input. |
| `suggest` | action | For text: people or other things to mention (below). |

**Values sent in `form`:**

- `checkbox`: a boolean
- `multiselect`: a list of the chosen values
- `hidden`: its `value` unchanged
- every other kind: a string, including `number`

**`suggest`:**

- When the user types `@` and a few letters, Task Proxy runs the action with the letters as `query` in its params. The result's `options` are the suggestions.
- A picked suggestion is written as `@` and its label.
- The form also sends `<name>.mentions`: an object from each `@Label` written to its value.

**Buttons:**

- **`submit`** sends the form.
- **`cancel`** runs without the form's values.
- **`buttons`** sit before the submit button, such as `toggle` buttons for panels of more fields.
- **`children`** are drawn below the buttons. The values of any `inputs` among them are sent with the form.

**A host action as `submit` (0.1.3):** the form's values fill that host action's fields of the same name, so a form with a `name` field and `git.createBranch` as its submit creates the branch the user typed. Only the host action's own fields are filled. Older hosts use the fields as the plugin sent them.

**`changed` (0.1.4):** once any of the form's fields differs from the value it was drawn with, the submit button shows and runs `changed` instead of `submit`, and goes back when the values do. A search form uses it to show Refresh until its search is changed, then Search. Older hosts always show `submit`, so both actions **SHOULD** do something sensible with the form's values.

**`inline` (0.1.2):** lays the fields and buttons out in one row, sharing its width and wrapping when there is no room. Without it, a form with one short field already sits on one line. Older hosts stack the fields, so it is safe to send to any host.

### 8.5 Host actions

A host action is something Task Proxy does itself, and only when the user clicks the button or link that names it. It is never run from a plugin's call, so a plugin cannot change the user's repo or open a page without a click that says so.

| `type` | Fields | Does | Needs |
|---|---|---|---|
| `git.createBranch` | `name` | Creates a branch from the current one in the open project's selected repo, and switches to it. Refused when `name` is not a valid branch name. | `git: createBranch` |
| `openUrl` | `url` | Opens the address in the user's browser. HTTPS only. | nothing |
| `copy` | `text` | Copies text to the clipboard. | nothing |
| `openSettings` | — | Opens the plugin's settings in the Plugins drawer. | nothing |
| `toggle` | `key` | Shows or hides the `panel` with that key, on the page or in its dialog. | nothing |

### 8.6 Icons

Icon names come from the Web UI icon set that Task Proxy loads from its CDN. The whole list is at `https://cdn.myfi.ws/icons/all.json`, and the Icons & Emojis drawer in Task Proxy shows them. Examples are `ticket`, `list`, `plus`, `bell`, `link`, and `xmark`.

An unknown name draws a placeholder diamond, so check every name against the list. The set can grow without a spec change, but a name that exists **SHOULD NOT** be removed from it, since released plugins use it.

## 9. Publishing

These rules apply to plugins in Stoic Dreams' catalog at `https://cdn.myfi.ws/apps/task-proxy/plugins/catalog.json`.

**Catalog entries:**

- Each entry holds the manifest's `id`, `name`, `version`, `spec`, `apiVersion`, `description`, `category`, `icon`, and `permissions`, plus the URLs and signatures of `plugin.json` and `plugin.wasm`.
- An entry may list older versions in `versions` (0.1.1), each an entry of its own. Task Proxy offers the newest version it can run (README, "Compatibility").
- An entry Task Proxy can't read is skipped, without hiding the others.

**Signing:** both files are signed with the Task Proxy update key, as `cargo tauri signer sign` writes it. Task Proxy refuses an install if:

- a signature doesn't match
- the signed manifest asks for other permissions than its entry shows
- the download's id or version differs from its entry

**Downloads:** both files are downloaded only from under the catalog's folder, at most 20 MB each.

**Published versions are never changed or removed.** A fix is a new version.

## 10. Draft 0.1.4: processes

This patch is for the Task Manager plugin, which lists running processes, including stuck background ones, and closes them. It also adds `theme` to table rows and `clip` nodes (section 8.2), `side` to `navigate` (section 7), and `changed` to forms (section 8.4), which older hosts ignore. It is a draft: no Task Proxy release supports it yet, and it may change before it is released.

### 10.1 The `processes` permission

`"processes": ["list"]` or `["list", "stop"]`.

| Value | Allows |
|---|---|
| `list` | The `processes` host call. |
| `stop` | The `process.stop` and `process.kill` host actions. It needs `list` too. |

Task Proxy refuses a manifest that asks for `processes` and also for `hosts`. Command lines and folders can hold secrets and private paths, so a plugin that can read them **MUST NOT** be able to send anything off the machine.

### 10.2 The `processes` host call

**Request:** `{"op": "processes"}`.

**Answer:** `{"processes": [...], "ownPid": number}`, where `ownPid` is Task Proxy's own process. It lists only processes the user owns, never other users' or the system's. Each process is:

| Field | Type | Meaning |
|---|---|---|
| `pid` | number | |
| `parentPid` | number or `null` | |
| `name` | string | |
| `command` | string[] | The program and its arguments. |
| `cwd` | string or `null` | Its working folder, when the platform reports it. |
| `started` | number | When it started, in milliseconds since the Unix epoch. Together with `pid`, this names one process, since pids are reused. |
| `cpu` | number | Percent of one core, averaged since the last `processes` call. |
| `memory` | number | Resident memory in bytes. |
| `ports` | `{"port", "protocol", "address"}[]` | TCP ports it listens on, and UDP ports it has bound. |
| `orphaned` | boolean | Its parent exited, so it now belongs to init, `systemd --user`, or `launchd`. On Windows, its parent pid no longer exists. |
| `inProject` | boolean | Its working folder is inside the open project. |

### 10.3 The `process.stop` and `process.kill` host actions

**Fields:** `{"pid", "started", "tree"}`.

- **`process.stop`** asks the process to end: SIGTERM, or on Windows a close request.
- **`process.kill`** ends it: SIGKILL, or on Windows termination.
- **`tree: true`** also ends its child processes, children first.

**Before acting, Task Proxy:**

- refuses when the pid's start time is not `started`, since that pid is now another process
- refuses Task Proxy's own process and its ancestors
- refuses processes the user does not own
- asks the user to confirm, naming the process, its pid, and its command, even when the action has its own `confirm`

### 10.4 Open question

Processes belong to the whole machine, not to a project, but section 6.1 says a plugin shows only in projects set up for it. One option is to turn the Task Manager on for each project and filter to that project's processes by default, which needs no change to section 6.1. The other is a kind of plugin that shows in every project once it is turned on, which would need its own rule. This is decided before 0.1.4 is released.

## 11. Proposed for later patches

These are not part of the spec yet. Each would be a patch, since it only adds.

**More contribution points:**

- a panel in Task Proxy's right drawer
- commands in a command list
- hooks before and after a commit, which may stop a commit with a reason

**More host calls and actions:**

- **Project info:** the open project's name and id, but not its path unless a permission allows it.
- **More git, behind new `git` values:**
  - read-only: status, the remote URL, and the list of repos
  - actions: commit and push, only from a click
- **Running a script:** a host action, after a click and a confirmation that shows the script, which runs one of the project's saved scripts in a Task Proxy terminal.

**Projects asking for plugins:** a `.taskproxy/plugins.json` listing the plugins a project wants, which Task Proxy offers to install and never installs on its own.
